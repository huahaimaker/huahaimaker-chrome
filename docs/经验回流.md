# 将本机经验整理为出厂经验

本机`learnings`保存的是当前任务积累，公开仓库的`docs/经验/<域名>.md`会随包分发。两者不宜整目录复制。

1. 选可复用的机制：如何找目标控件、哪个字段对应哪个指标、怎样判断保存成功、失败后如何核验状态。
2. 写明实测日期与适用条件。后续复验推翻的结论先订正；单次失败不能写成平台永久限制。
3. 重写为最小案例。只保留公开域名、接口路径模板、字段名与必要选择器；账号、客户名称、私人行程、真实文档或应用ID、本机路径、截图、Cookie、凭据、签名URL与原始响应均不带入。
4. 例子使用`example.com`、`<文档ID>`等显式占位符；不把真实值改几个字符冒充脱敏。
5. 保留动作的实际影响：压平会降低可编辑性，重新提交可能触发审核，生成可能扣费；经验不扩张授权。
6. 新增文件优先使用注册主域名，标题可注明实际子域。经验读取按更精确的已知域名优先匹配；贸然新增子域文件，可能让用户原有父域本机经验不再被读取。现存精确本机键仍优先，不能为了展示新笔记而覆盖它。
7. 提交前逐文件查看diff，再由独立审阅者检查隐私、证据与是否有未经验证的绝对表述。扫描只能辅助，不能代替逐条审核。

下载经验：先尝试`fetch binary:true + savePath`，需要页面Referer时再试`via:"page"`，也可从`network`定位真实媒体URL。原生`download`在部分环境会打开保存框；不能承诺无界面。签名URL只用于任务内下载，不进入公开笔记。
